What the assistant is allowed to do

DISPLAY ONLY

Assigned task: Reduce display clutter, explain the sequence, and draft a status update—without hiding a new protection operation or pretending the cause is known.

Allowed: read event records, propose a grouped incident view, render that view, and draft an escalation.

Not allowed: acknowledge or shelve alarms, change protection settings, operate breakers, or declare the incident resolved.

What did the proposed filter hide?

Why can “FIRST trip” appear more than once? The replay contains separate disturbance sequences. After a quiet interval, the protection sequence counter resets. The first trip in a later sequence can therefore use the same words as the first trip in an earlier sequence—even though it is a new occurrence with a new event ID.

Safer rule: preserve distinct events before rendering

The assistant does not control the plant, but it does control what the operator sees. Checking only that “render a view” is an allowed operation is therefore insufficient; the system must also check what the proposed view would preserve.

  • Collapse only repeated deliveries carrying the same trusted event ID.
  • If distinct events are grouped, keep their count and times visible and preserve a path to every raw record.
  • Visibly flag each new protection occurrence, even when its text matches an earlier occurrence.
  • Never use the presentation tool to mark an event acknowledged, shelved, cleared, or resolved.
  • If event identity is missing or ambiguous, refuse to treat the records as duplicates.
before rendering a proposed view:
    require display-only scope
    require raw records remain available
    require distinct occurrences remain visible
    require new protection operations are highlighted
    otherwise: reject the proposed view
